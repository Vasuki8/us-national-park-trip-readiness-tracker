# Reviewed park-profile publication contract

Ordinary engineering under the owner's permanent autonomy policy. This increment
uses synthetic sources only; it records no real approval or public promotion.

## Scope and decision

Use an optional, paired `data/park-profiles.json` and
`data/profile-source-rights.json`. Both absent preserves the existing pilot;
one missing or either invalid refuses the build and blocks the affected release
gates. Do not seed placeholder public profiles. Reuse the complete normalized
profile snapshots, including degraded states, original observation/check clocks
and null publisher/publication clocks. All five retained profiles are required.
The public projection excludes private checkpoint IDs and ancestry.

Rights use a separate exact-scope manifest for normalized profile text and
category names. Bind each park, profile ID, source URL and semantic content hash;
require exact official-policy URLs, third-party/media/marks exclusions and an
actual review clock at or after collection. The existing guidance manifest does
not approve this text. The official NPS API guide directs users to the NPS
disclaimer; API origin alone is not a reuse licence. Exact material still needs
review. No images or new licences are introduced.

An immutable private reviewed bundle contains the verified checkpoint, exact
public projection, rights manifest and explicit approval metadata. Approval binds
checkpoint ID and complete projection/rights digests and occurs after collection
and rights review. Integrity hashes are not signatures or independent proof of
a person's review. Creation requires an explicit approval operation.

Offline promotion preparation emits only a Git patch for the paired public
files, binds their exact previous bytes or absence and the reviewed bundle, and
refuses rewinds and unsupported changes to retained data after degraded checks.
An offline check regenerates the patch and candidate identity immediately before
separately authorized application. It does not apply, deploy or approve data.

Once the public pair exists, the existing durable review, source rights and
backup gates also require matching profile evidence. A fresh verified reviewed
bundle copy in a separate private parent supplies local recovery evidence;
remote transport/fresh-download receipts remain deliberate operator work and
are not inferred from that copy. Older entry-ledger/alert backups cannot cover
profiles. Existing provider freshness and hosting limitations remain explicit.

## Validation

Synthetic Python and Node tests cover exact fields, source scope, hashes, missing
fields, seasonal/category typing, nullable clocks, degraded retention, approval
and rights mismatches, private storage, immutable writes, paired promotion,
changed bases and backups. Compare both language validators with an actual
synthetic Python projection. Run the complete supported CI before integration.
